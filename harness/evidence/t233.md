# Ticket 233 image qualification

The image and repository overrides are implemented. Full PB qualification is
blocked by 29 function selectors requiring access outside the current harness
boundary. The failures remain failures. No tests were forced to skip or pass.
Live TL3 configuration and services were not changed.

## Inventory and proof

The first inventory ran before image changes and was posted early on
[#233](https://github.com/RobTand/trustladderiii/issues/233#issuecomment-6553690335).
The image ID and supplementary findings were posted in a
[second comment](https://github.com/RobTand/trustladderiii/issues/233#issuecomment-6553719985).

The original image produced 224 passed selectors, 18 assertions, 11 errors,
and one uncollected helper. The helper was explicitly disabled by PB and was
removed from the final selectors. Seven GPU parser selectors passed in the
supplement. The new image produced 231 passed selectors, 18 assertions and
11 errors across the combined 260 selectors. No missing Python import was
observed, and nothing required upgrading pytest to 9.1.

The new-image compiler resolves the original missing-tool failure. The same
native selector then reaches `ctypes` and fails with `failed to map segment
from shared object` on a library under `/tmp`. The other remaining failures
are also host/execution-boundary requirements:

| File | Failing selectors | Classification and cause |
|---|---:|---|
| `test_checkout_recovery_1472.py` | 1 | Host/container privilege: temporary shared libraries cannot be mapped executable. The old image also lacked a C compiler. |
| `test_dependency_digest_contract.py` | 5 | Host/container privilege: executing a copied Python binary from temporary storage returns permission denied. |
| `test_git_runners_1307.py` | 7 | Host/container filesystem: the exported `/checkout` has no `.git`. |
| `test_sealed_bundle_cache.py` | 16 | Host/container filesystem: PB qualifies ext4, xfs, btrfs and zfs for cache scratch; the harness supplies tmpfs, so cache sessions decline it. |

None requires a production-code repair in this ticket. Root, GPU access,
shared mounts, executable scratch, Git metadata and writable host mounts were
not added. The full-file proof therefore does not meet the ticket's condition
that every selected PB test pass or skip. Pilot plans must avoid these named
requirements, or the execution boundary needs a separate reviewed change.

The future files `test_snapshot_sealed_git_identity.py`,
`test_docker_shim_gpu_options.py`, and `test_transition_lock_denial_1515.py`
are absent from the selected PB main. Existing coverage chosen for #2419 is
`test_git_runners_1307.py` and `test_submission_git_deadline_1888.py`; for
#1968, `test_gpu_runtime_vendor_identity.py`; and for #1515,
`test_measurement_reservation_census_1419.py`. The other four pilots use their
existing named files.

The sandbox suite passes all 317 selectors across 39 files through
`run_checks` in the new image. Its initial all-files plan returned `no-report`
because the expanded collection record exceeds the runner's 64 KiB record
limit. Even the static lower bound without parameter IDs is 68,038 bytes.
The final proof calls `run_checks` once per file in one admitted action and
continues cumulative PB progress. The report limit was preserved.

The existing harness verifier also passes its verdict and containment checks.
