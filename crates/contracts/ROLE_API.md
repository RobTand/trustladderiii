# Rust role contracts

Generated by `tl3-contracts-schemas` from the shared Rust form.

`RoleContract` associates typed Input, Reply and Facts. Each role table is `Vec<Rule<F>>`; the default facts are `RoleFacts<Input, Reply>`. A consumer may supply a richer facts type without introducing a controller dependency. `validate_input` and `validate_reply` deserialize through the existing role types. `render(RenderOptions)` returns prompt suffix, model-facing schema and guidance. `evaluate(&Facts, &Policy)` returns resolved violations in check order and stops after a failing gating rule.

`Rule<F>` has check `fn(&F) -> Vec<F>`, names `fn(&F) -> Vec<Name>`, bad_value `fn(&F) -> Value`, allowed and repair callbacks. `Callback` is Static, Facts `fn(&F) -> T`, or Role `fn(&F, Role) -> T`. `Registration<F>` carries example, complete before reply, witness and with_reply `fn(&F, &Value) -> F`. Role callbacks require explicit `Witness::ByRole` entries for every declared role. Mixed repairs resolve independently per role. Source-only rows require a null witness. A mixed SourceEdit and field-Edit set requires the complete edited reply witness; only unresolved SourceEdit rows may remain after rechecking that reply. CantMeet satisfies that role's terminal predicate, and Edit witnesses pass guard and check.

`Policy` carries terminal predicates, source editors and optional schema_membership `fn(SchemaKeyword, &Value, &Value) -> Result<bool, String>`. The arguments are keyword, resolved constraint value and candidate JSON value. Adapter errors propagate through registration and guards, never fail open. Enum/const/type membership preserves strict JSON value types; other schema constraints require that consuming validator. Callbacks and policy never serialize. `render_all` takes the closed RenderContext enum at the call boundary, including empty aggregates. Reply is default; Tool omits CantMeet's terminal phrase, preserves SourceEdit and rejects Edit. `permits` grants only independent Edit pointers, with CantMeet terminal precedence. Empty evidence preserves refusal output.

SourceEdit uses a repository-relative path matching its path/symbol subjects and a nonblank instruction of at most 1024 UTF-8 bytes. The instruction byte cap is enforced at deserialization as well as validation. JSON Schema maxLength counts characters, so the schema description states the authoritative UTF-8 byte unit. This is an explicit new Rust boundary; no existing Python or harness API changes.

Evidence is producer-redacted before construction. At most 16 records, 4096 UTF-8 excerpt bytes and 64 failing targets persist. Excerpt truncation includes literal newline plus `[truncated]` inside the byte cap. Whole-item overflow increments evidence_truncated; target overflow increments failing_targets_truncated. Counts persist across replay and render as omitted-count markers. Schema maxLength is a character bound; Violation normalization at serialization/deserialization and rendering enforces the excerpt UTF-8 byte cap. A schema-only validator must not treat character counts as byte counts. These limits never clip independent violations or the whole message. The harness R1 65536-character and byte-budget fail-loud boundaries remain with its adapter.

Later stdlib-only Python adoption must retain role, evidence and order through proof_rules.violation_data and ProofRefusal.for_check. Backend labels/case identifiers belong in TestFailure.target/test, never Name.

The wire schema is [schema/violation.json](schema/violation.json). Rustdoc documents the callable interface. Four remaining role reply roots are generated in contracts; budget-wire and harness-wire retain their controller owners, quota-event retains QuotaEvent. `tl3_controller::contract_schemas::generated` aggregates all artifacts without reversing dependencies.
